# M3.5C live M1–M3 wiring

The guarded entrypoint is `examples/evaluation/live-validation.mjs`. It accepts `--dry-run` or `--live`, with optional `--generation-0` and `--stop-after STAGE`; Generation-0 is opt-in and is appended only after `EVALUATE`, while the default invocation retains the original 13 stages. Dry-run validates local inputs and configuration without constructing a model or OpenAlex client call. A live invocation runs the existing `ResponsesModelGateway` after the existing model preflight succeeds. An intentional stop marks later stages `INTENTIONALLY_NOT_RUN` and the run `STOPPED_AS_REQUESTED`. When `--stop-after REPORT` is requested, REPORT finishes and persists `report.md`, then the run snapshot records `status: STOPPED_AS_REQUESTED` and `stopAfter: REPORT`; there are no later stages to run.

All model entrypoints use `resolveModelConfiguration`: process environment values override the project-root `.env`, and a missing `.env` is valid when the required process values are present. The zero-network startup check is:

```powershell
node examples/evaluation/model-config-check.mjs
```

It reports `CONFIG_READY` only after local URL, placeholder, required-value, and mode validation. It reports the selected model, a credential-free Responses endpoint, configuration sources, and `ResponsesModelGateway`; it never performs TCP, HTTP, model preflight, or OpenAlex calls. `CONFIG_READY` is therefore a configuration result, not connectivity evidence. Use either (A) all five model variables in the current PowerShell process, or (B) put the base URL, model, provider, and run modes in `.env` while keeping `EVORESEARCH_MODEL_API_KEY` in the process environment. The key may also be stored in the ignored local `.env` when the operator accepts plaintext storage. The `.env.example` file contains placeholders only. A local `.env` is plaintext and ignored by Git; it must never be committed or included in a handoff bundle.

Model preflight is a separate bounded boundary. It permits at most two attempts and retries only trusted `RATE_LIMIT` or `SERVER_ERROR` classifications, including equivalent structured statuses carried by an HTTP 200 SSE error event. Authentication, configuration, malformed-response, and unclassified provider errors fail closed without retry. `model-preflight.json` records bounded per-attempt transport and provider diagnostics; preflight attempts are reported separately from the scientific `RunBudget` model-call ledger.

ProblemExtractor uses the existing prompt-json contract and permits at most one configured serialization retry for either gateway-reported JSON parse failure or parsed output that fails schema validation. Parse failures retain `INVALID_RESPONSE`, `parseStatus: failure`, and `schemaValidationStatus: not-attempted`; the domain result uses `failureKind: SERIALIZATION`, and `retryable` records whether the local retry allowance remains. Schema failures retain `SCHEMA_VALIDATION_FAILURE` and `failureKind: SCHEMA`. Provider/transport failures do not consume the serialization retry. A retry uses the existing correction request with unchanged scientific input and a distinct attempt ID; both actual calls pass through the existing role/global budget admission and retain independent diagnostics and output hashes. No JSON repair occurs. Earlier successful per-paper outputs remain auditable, but the downstream aggregate is available only after every required paper succeeds. A terminal failure stops the stage; a new run recomputes all papers in a new directory.

`LITERATURE_SEARCH` requires an explicit case-level `corpusCutoff` in `YYYY-MM-DD` form. The run snapshot records the effective cutoff and OpenAlex search policy; missing or malformed publication dates are excluded from the cutoff corpus and counted in `SearchCoverage`. Each query also persists a `LiteratureQueryMembership` record in `literature-query-membership.json`. `SOURCE_SELECT` ranks only the records in that query's membership, while retaining the retrieval need, origin problem nodes, coverage ID, and coverage status in every selection. Its score is pure and deterministic: Unicode letter/number tokenization, distinct lower-case query tokens, conservative ordinary-word removal, token-boundary matching, the existing identifier and cutoff-date bonuses, and the existing literature-ID tie-break. `FAILED` and `NO_RESULTS` coverage produces an empty membership and cannot select or extract evidence; `PARTIAL` coverage remains explicitly labeled.

`EVIDENCE_EXTRACT` uses one selected source as its operation unit. Before any model call, the coordinator writes `evidence-plan.json`, reserving one model call plus the configured serialization retry allowance per operation against both the EvidenceExtractor role budget and the global model budget. Operations that do not fit are persisted as deferred, and the completed run is marked `scientificallyComplete: false` while `incompleteCoverage` is true. Claims and materialized evidence carry the same query-local provenance path through extraction, so source metadata and model interpretations remain auditable.

EvidencePlan admission uses rank-first round-robin across RetrievalNeeds: preserve the persisted SourceSelection array order and record ranking within each need (concatenate multiple query paths in their persisted order), allocate first choices across needs before second choices, and order needs by stable `retrievalNeedId` within each round. `operationId` is the final tie-break and remains `retrievalNeedId:queryId:literatureId`; shared records across queries stay distinct operations. No relevance scoring is performed by the scheduler. When slots are fewer than selectable needs, later needs remain explicitly deferred; full need coverage is not implied. The model-call/retry reservation and coverage schema are unchanged. Coordinator-added open-question targets remain unsupported unless an actual Evidence relation exists.

The compact offline fixture `tests/fixtures/evidence-plan/first-fresh-source-selection.json` preserves the 44 selected identities, record order, and provenance fields from `run-2026-10-04T05-14-44-337Z-66422045`; titles are diagnostic only. Run `node scripts/compare-evidence-plan.mjs` to compare the historical operation-ID ordering (6 operations, 2 needs) with the scheduler (6 operations, 6 needs, 38 deferred). This fixture is a scheduling regression, not scientific ground truth; it does not read or modify the historical run during replay.

`EVALUATE` reads the persisted evidence plan, execution outcomes, evidence graph, evidence items, and search coverage. Its `evidenceAssessment` summary records selected, planned, completed, failed, deferred, and zero-item operations plus retrieval coverage states. Exhaustiveness is deterministic and never inferred from the evidence-item count; deferred or failed work, unexecuted planned work, and failed or partial retrieval keep the assessment incomplete.

`REPORT` renders those states for readers in an explicit evidence-limitations section. It calls out incomplete coverage, deferred work, `NO_RESULTS`, failed retrieval, successful-empty extraction, abstract-only evidence, and deterministic source-relevance warnings. These are reported as limits on what the run establishes; they are not rendered as novelty, falsity, truth, absence, negative evidence, provenance defects, or completeness claims. Abstract-only evidence is explicitly bounded away from full-text, experiment, equation-level, and quantitative verification.

The EvidenceExtractor request carries an explicit `EvidenceExtractorOutput` contract in prompt-json mode: the model must return `claimId`, `literatureId`, and `items`, with an empty `items` array allowed when the selected source is insufficient. Coordinator-owned identifiers are supplied separately from the untrusted source snapshot, echoed for validation, and replaced by the trusted input only after exact matching. Structural failures are recorded on the model-attempt ledger with their JSON path and one bounded serialization retry receives the same validation error and contract; provider failures do not consume that serialization retry.

Paper and retrieved literature text is nested as untrusted data in model requests. Source evidence levels are checked against the available abstract/full text before materialization; model interpretations carry model provenance and cannot be emitted as source evidence. Historical runs created before query memberships and evidence plans are retained as historical artifacts and are not replayable under this provenance contract.

Generation-0 is now an explicit opt-in extension. The default 13-stage path and `--stop-after REPORT` behavior remain unchanged. `node examples/evaluation/live-validation.mjs --live --generation-0 <case.json>` runs `EVALUATE` and then the shared `runGeneration0Extension` service, which validates the persisted problem/evidence state, calls the existing GapDiscovery and Generation-0 ports, persists `gap-discovery.json`, `generation-0.json`, `generation0-extension.json`, `events.json`, and `checkpoint.json`, and renders a bounded report before stopping. The service accepts real artifact IDs from `ingest.json`; a saved-run importer can supply `sourceRunId` separately. Deterministic gaps and model gaps remain separately identifiable, coverage-only gaps cannot generate hypotheses, and a failed GapDiscovery contract blocks dependent Generation-0. A legal empty model envelope is recorded as `COMPLETE_EMPTY` with `acceptedHypothesisCount: 0`; it is not reported as a scientific discovery.

The shared extension uses one run identity for its output directory, state, checkpoint, events, and report. Events include stage boundaries, model attempts, accepted hypotheses, and checkpoint position. `FileGeneration0RunStore` atomically commits EVALUATE, GAP_DISCOVERY, and GENERATION_0 boundary records, preserves immutable config/cutoff/source lineage, and leaves an `INTERRUPTED/UNKNOWN` marker if an external attempt was not committed. Checkpoint state hashes are computed over the persisted gap/population state. Replay of already committed extension artifacts must validate those hashes and IDs before any provider call; the current live M3.5C coordinator exposes the boundary, while full DSH session/storage integration remains deferred.
