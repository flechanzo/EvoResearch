# Milestone 4A: evidence-grounded gap discovery and Generation-0 seeding

M4A is an isolated boundary over accepted structured state. `discoverResearchGaps` reads a `ResearchProblemGraph`, the available `EvidenceGraph` records, and the EVALUATE completeness summary. It emits deterministic `ResearchGap` records. Scientific gap kinds are distinct from coverage kinds; coverage-only records are marked `COVERAGE_FOLLOWUP_REQUIRED` and cannot seed a hypothesis.

`generateGeneration0Hypotheses` validates every persisted gap before selecting candidates or invoking a model. An eligible `MIXED` gap must retain independent graph, claim, or direct-evidence provenance; coverage-only gaps remain non-generative. Candidates retain problem, claim, and direct evidence IDs and include a proposed mechanism, expected mechanism, uncertainty, falsification conditions, expected observable, and discriminative experiment idea. They do not contain novelty evidence or novelty estimates and never acquire a validated or supported status from generation alone. Dedupe uses the normalized gap, mechanism, and expected-test signature and records each duplicate decision. Replaying the same accepted input with the same timestamp and sequence is deterministic and idempotent.

The optional `ModelGateway` path uses the existing structured gateway contract and fails closed when output is malformed or provenance references do not resolve. The default path is deterministic and offline. `buildM4AArtifacts` produces `gap-discovery.json`, `hypotheses-generation-0.json`, and an existing-domain `Checkpoint` plus `hypothesis.created`/`checkpoint.created` event envelopes. `persistM4AArtifacts` writes only the two M4A artifacts and checkpoint; callers append events to their existing event store. The shared `runGeneration0Extension` coordinator is the integration boundary used by both the opt-in M3.5C path and the saved-run importer; it validates graph/claim/evidence links, carries real artifact IDs, blocks Generation-0 on failed GapDiscovery, and emits ordered stage/model-attempt/hypothesis/checkpoint events.

M4A remains opt-in after EVALUATE; the default validated M1–M3.5 stage list is unchanged. This extension does not constitute DSH integration or full Phase-1 orchestration.
