# Milestone 4B: bounded hypothesis evolution

M4B consumes accepted M4A hypotheses together with structured reviews, criticisms, and direct evidence. It applies deterministic mutation proposals without experiments or model calls. Every accepted mutation has an existing parent hypothesis, a review linked to one or more specific criticisms of that parent, non-empty direct evidence IDs, a declared canonical `MutationType`, and an immutable `MutationEdge` projection carrying those criticism IDs.

Parents are never edited in place. A child advances the generation, references its immediate parent, retains the M4A gap and source provenance fields exactly, and records the linked criticism and mutation edge. Mutation fields must describe an actual changed hypothesis component. The child is marked `status: mutated` with `reevaluationRequired: true`, clears inherited evaluation dimensions and experiment results, and cannot imply improvement or survival. Model-interpretation evidence cannot be used to justify a mutation. The evolution result retains parents, children, mutation projections, and provenance so genealogy remains replayable.

`buildM4BArtifacts` emits deterministic `hypothesis.mutated` and `checkpoint.created` domain events. `persistM4BArtifacts` writes the evolution projection, mutation edges, and checkpoint while leaving event delivery with the caller. The checkpoint uses the existing domain checkpoint schema and hashes the canonical evolution projection. Replaying the same accepted input and compatible prior checkpoint produces the same child IDs, mutation edges, events, and checkpoint without repeating any model or experiment work.
